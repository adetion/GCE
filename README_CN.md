## 核心理念

GCE 是一个人工生命实验室与战略智能平台，在两个层面运行：

**第一层 —— 进化智能。** 100 个智能体诞生时携带着随机的表达式树"大脑"和 36 位特征掩码，决定了它们能感知什么。它们观察混沌环境，做出预测，凭准确度获得能量或走向消亡。高能量智能体通过锦标赛选择 + 交叉 + 变异进行繁殖，低能量智能体则被淘汰。环境并非随机噪声——它是 **Lorenz 混沌吸引子**与**多主体拍卖市场**的耦合，产生有结构却不可预测的时间序列。为了生存，智能体必须进化出对这种混沌的真正预测模型。

**第二层 —— 战略智能。** 当用户描述任意竞争场景（价格战、预算谈判、生态资源分配、人际关系冲突等），系统会解析场景，分类其**应用领域**，分析舆情情绪，使用精英进化智能体作为扰动源进行前向推演，执行 Lyapunov 混沌分析，并生成**双输出战略报告**：一份专业的四幕博弈论分析**加上**一份大白话结论卡片——包含具体可执行步骤，不用任何专业术语，只说"照着做就行"。

**没有训练数据。没有梯度下降。没有反向传播。** 只有进化。

## 工作原理

### 1. 环境 —— Lorenz 混沌 + 拍卖市场

环境在独立 `multiprocessing.Process` 中运行，以固定频率产生事件。每个 tick：

1. **Lorenz 吸引子**经 RK4 数值积分（`σ=10, ρ=28, β=8/3`——蝴蝶形奇异吸引子的经典混沌参数区）
2. **市场智能体**（趋势跟踪型、均值回归型、随机型）提交买卖报价，Lorenz 的 x 分量作为外部混沌源注入，影响智能体行为
3. **清算价格**由拍卖机制计算，Lorenz 的 z 分量作为结构化噪声叠加
4. `GCE_RawEvent`（含价格、成交量、价差、完整 Lorenz 状态 `(x, y, z)`）发布到共享 `multiprocessing.Queue`
5. 约 10% 的 tick 还会产生**文本事件**——从当前市场状态综合生成的新闻头条

选择 Lorenz 吸引子的原因：它产生**结构化不可预测性**——既不是纯随机（取平均即可应对），也不是简单周期（记忆即可应对）。确定性混沌迫使智能体进化出真正的非线性预测模型。

### 2. 智能体 —— 表达式树 + 特征掩码

每个智能体是一个独立 `multiprocessing.Process`，包含：

- **基因**：编码数学函数的表达式树。内部节点为运算符（`+`、`-`、`*`、`/`、`sin`、`cos`、`exp`、`log`、`abs`、`ifgt`）。叶节点引用 36 个特征槽之一，或持有一个数值常数。
- **掩码**：36 位整数，每位决定智能体是否"看到"对应特征。掩码=0 则智能体全盲；掩码=全 1 则全感知。
- **采集器 (Forager)**：维护最近 20 个事件的滑动窗口。每收到新事件，从窗口中提取 36 维特征并通过掩码过滤。
- **预测器 (Predictor)**：对掩码过滤后的特征向量求值表达式树 → 输出单一数值预测。

**特征池**（36 维）：

| 索引 | 特征 | 说明 |
|------|------|------|
| 0–19 | 价格滞后 1–20 期 | 20 个滞后时间步的历史价格 |
| 20–24 | 成交量滞后 1–5 期 | 5 个滞后时间步的历史成交量 |
| 25–29 | 价差滞后 1–5 期 | 5 个滞后时间步的买卖价差 |
| 30–32 | 价格 5/10/20 期 SMA | 价格的简单移动平均 |
| 33–34 | 价格/成交量波动率（5 期） | 滚动标准差 |
| 35 | 情绪分数 | 文本事件大小写/关键词启发式评分 |

### 3. 能量经济

能量公式是**唯一的选择压力**——没有独立的损失函数、没有梯度、没有反向传播：

```text
误差   = |预测价格 - 实际价格|
奖励   = base_reward × max(0, 1 - 误差 / error_scale)
```

- 完美预测（误差 = 0）→ `+base_reward` 能量
- 误差 ≥ error_scale → `0` 奖励（该预测毫无价值）
- 能量 ≤ 0 → 智能体死亡（进程通过 `terminate()` 终止，SQLite 中状态标记为 "dead"）

能量以较小基础速率持续消耗（存在的代谢成本）。只有持续准确预测的智能体才能积累足够能量存活并繁殖。

### 4. 繁殖 —— 锦标赛选择 + 遗传算子

每 `breeding_interval_seconds`（默认 2 秒），繁殖器线程执行：

1. **资格检查**：选取所有能量 ≥ `reproduce_threshold` 的智能体
2. **锦标赛选择配对**（规模=2）：每个亲代位置随机选 2 个候选，选能量较高者
3. **子树交换交叉**（70% 概率）：在双亲树中各随机选一个节点，交换所选子树产生子代
4. **变异**——均匀选择以下操作之一：
   - **终端变异**：改变特征索引或将数值常数抖动 ±20%
   - **函数变异**：将运算符节点替换为另一个同元运算符
   - **子树替换**：用新生成的随机树替换随机子树
   - **收缩/扩张**：删除子树（减少深度）或插入新运算符节点（增加深度）
   - **掩码位翻转**：随机切换一个特征可见位
5. **验证**：检查树深度和节点数约束；约束违反时最多重试 3 次
6. **插入**：将子代以 `initial_energy` 和 `generation = max(parent_gen) + 1` 写入 SQLite
7. **成本扣除**：从每个亲代扣除 `reproduction_cost / 2` 能量

### 5. 领域模板系统 —— 七大应用领域

系统不对金融/商业场景硬编码。**领域模板系统**（`gce/interface/GCE_domain_templates.py`）通过两阶段分类将任意用户场景映射至七个应用领域之一：

**第一阶段 —— 关键词打分（离线，始终可用）：**
每个领域模板定义 30–50 个中文关键词触发器。分类器统计用户输入中匹配的关键词数量并计算匹配分数。若某一领域的分数显著领先（>2 倍于第二名），则立即选中。

**第二阶段 —— LLM 歧义消解（在线，关键词分数接近时）：**
当多个领域的匹配分数过于接近无法区分时，由 LLM 判断场景最合适归属。

**DomainTemplate 提供什么：**
- `entity_type_hints`：该领域要寻找什么类型的实体（物种名/部门名/个人目标等）
- `value_semantics`：数值在该领域的含义（种群数量/预算金额/满意度评分等）
- `game_type_preference`：该领域最适合的博弈模型（生态→Cournot、个人决策→Negotiation 等）
- `parsing_prompt_additions`：场景解析时注入 LLM 系统提示词
- `sentiment_prompt_additions`：舆情分析时注入查询
- `narrative_prompt_additions`：叙事生成时注入系统提示词
- `narrative_term_overrides`：金融术语→领域术语的键值对替换表（如"价格"→"种群数量"）
- `plain_language_additions`：结论卡片的领域特定比喻和语言

**关键设计规则**：模板只描述"要找什么类型的东西"，绝不包含硬编码的实体名称、具体数值或领域公式。模板是参考参数，不是数据。

### 6. 场景解析 —— LLM + 正则双模

解析器（`gce/interface/GCE_parser.py`）从自由格式自然语言中提取结构化博弈场景：

**在线模式（LLM）：**
- 调用 LLM，系统提示词包含领域模板的 `parsing_prompt_additions`
- 提取：参与方名称、初始位置/价格、博弈类型、时间跨度、目标
- 领域特定的实体识别（如生态领域的物种名、企业领域的部门名）
- 解析后自动调用舆情分析

**离线模式（正则）：**
- 基于模式的中文文本参与方提取（人名、实体名等）
- 基于关键词启发式检测博弈类型（价格/拍卖/谈判/产量/竞争）
- 数值提取用于初始位置
- 限制：约 2 个具名参与方；其余检测到的玩家使用回退名称（Entity-A、Party-3 等）

两种模式均产出 `GCE_Scenario` 数据结构：
```python
participants: List[GCE_Participant]  # name, initial_position, strategy_hint
initial_prices: List[float]          # 各参与方初始数值
time_steps: int                      # 推演时间跨度（默认 30）
objective: str                       # 解析出的目标/背景
game_type: str                       # price_war | auction | negotiation | output_competition
domain_id: str                       # 匹配的领域模板 ID
sentiment_context: Dict[str, Any]    # LLM 舆情分析结果（或空）
```

### 7. 舆情分析 —— LLM 驱动的领域心理学

舆情模块（`gce/environment/GCE_sentiment.py`）提供结构化心理层，调制推演过程：

**`GCE_analyze_sentiment(scenario_text, entity_names, llm_client, domain_id)`**
- 以领域特定的舆情分析提示词调用 LLM
- 领域模板的 `sentiment_prompt_additions` 引导 LLM 关注该领域相关的情感维度
- 返回结构化 JSON：
  - `overall_sentiment`：正面 / 负面 / 中性
  - `sentiment_score`：浮点数 [-1.0, 1.0]
  - `key_themes`：该领域相关的叙事主题列表
  - `market_mood`：描述性标签（领域适配，如"保护紧迫感"而非"市场恐慌"）
  - `volatility_expectation`：预期情绪驱动的波动
  - `entity_sentiments`：各实体的情绪细分
- LLM 不可用时优雅回退至中性

**`GCE_compute_sentiment_bias(sentiment_context, game_type, player_name) -> float`**
- 计算受情绪调制的逐玩家扰动偏差
- 正面情绪 → 进攻偏差（提价、高出价）
- 负面情绪 → 防守偏差（降价、低出价）
- 截断至 [-0.5, 0.5]，由 `sentiment.influence_weight` 缩放
- 在四种博弈模型的前向推演中全部应用

### 8. 博弈推演引擎

引擎（`gce/simulation/GCE_engine.py`）使用精英进化智能体运行迭代前向推演：

1. **博弈模型选择**：使用解析器确定的 game_type（或从场景目标自动检测）
2. **精英智能体加载**：从 SQLite 按能量选取前 K 个智能体；无智能体时回退至 NGRC 风格多项式残差扰动
3. **迭代前向推演**：每个时间步 `t`：
   - 每个精英智能体独立预测下一共识值
   - 精英预测的中位数成为下一共识值
   - 逐玩家计算情绪偏差并与智能体扰动合并
   - 独立追踪各参与方轨迹
4. **混沌分析**：
   - **Lyapunov 指数估计**：量化轨迹混沌程度（正值 = 混沌，负值 = 稳定）
   - **分岔检测**：微扰分析识别微小变化导致大分岔的关键决策点
   - **轨迹波动率**：步间变化的滚动标准差
   - **纳什收敛度**：衡量系统距稳定均衡的距离
5. **关键事件检测**：识别各参与方轨迹中的重要事件（重大让步、中标、进攻动作）

### 9. 叙事生成 —— 双输出战略报告

叙事器（`gce/interface/GCE_narrator.py`，约 1300 行）为每个场景生成**双输出**报告：

**在线模式（LLM）：**
- 系统提示词包含领域模板的 `narrative_prompt_additions`，指导领域适配语言
- LLM 接收所有计算数据（轨迹、Lyapunov、纳什收敛度、参与方轨迹、舆情背景、关键事件），一次性生成专业报告和大白话卡片
- 第五章（大白话结论卡片）在系统提示词中作为必须章节规定

**离线模式（规则引擎）：**
- 四幕均由实际计算数据驱动构建——不使用静态模板
- 领域术语通过字符串级 `narrative_term_overrides` 替换（长键优先匹配，防止子串误伤）
- 大白话卡片由 `_build_plain_language_card()` 结合领域语言包生成
- 多方（3+）博弈自动触发分层权重排名

**报告结构：**

| 幕 | 标题 | 内容 |
|----|------|------|
| 一 | 战场全息重构 | 动力学体制鉴别（混沌/收敛/稳定），Lyapunov 分析，轨迹趋势，纳什收敛度，均衡估计 |
| 二 | 对手心智镜像 | 逐参与方行为分析，进攻/防守模式，关键转折点，情绪调制倾向，总体战略态势 |
| 三 | 博弈树全展开 | 2–3 条分支路径，含估计概率、触发条件、结果描述；分岔感知路径分析 |
| 四 | 策略指令下达 | 即时行动（1–3 步），中期布局（5–15 步），止损/止盈边界，监测计划，具体数字 |
| 五 | 大白话结论卡片 | 零术语可执行总结：一句话策略含具体比例，大白话"为什么"，分步操作含监测阈值，收尾类比 |

## 四种博弈模型

引擎支持四种经典博弈论模型，每种产生不同的轨迹动力学：

### 1. Bertrand 价格竞争（`price_war`）

n 家企业进行差异化产品价格竞争。每家企业定价以最大化利润（考虑竞争对手价格）。模型捕捉：
- 最优反应动态：每家企业降价抢市场份额
- 需求弹性随玩家数量缩放
- 纯 Bertrand 向边际成本定价收敛；产品差异化下向边际成本之上收敛
- 情绪偏差：正面情绪 → 激进定价；负面 → 防守性降价

### 2. Vickrey 拍卖（`auction`）

第二价格密封投标拍卖。每个投标人提交私密出价；最高出价者中标但支付次高出价。模型捕捉：
- 理论上诚实出价是占优策略，但情绪和扰动导致偏离
- 投标人对竞争者估值有噪声估计时出现出价阴影
- 扰动下的收入等价动态
- 情绪偏差：正面情绪 → 高出价（激进）；负面 → 谨慎出价

### 3. 交替出价谈判（`negotiation`）

两方或多方轮流提议资源分配方案，含时间折现。模型捕捉：
- Rubinstein 讨价还价动态：先动优势，不耐驱动的让步
- 多方联盟形成：识别天然盟友，孤立僵持者
- 完全信息下向纳什谈判解收敛
- 情绪偏差：正面情绪 → 更坚定立场（少让步）；负面 → 更快让步

### 4. Cournot 产量竞争（`output_competition`）

n 家企业进行产量（而非价格）竞争。每家企业选择其产量（考虑竞争者产量）。模型捕捉：
- 策略替代：竞争者增产，你减产
- 市场价格由总产出通过逆需求函数决定
- 向 Cournot-Nash 均衡产量收敛
- 情绪偏差：正面情绪 → 扩张产量；负面 → 收缩

### 博弈类型检测

解析器从用户场景描述中的关键词自动检测合适模型：

| 关键词（中文） | 博弈模型 |
|---------------|----------|
| 价格、定价、降价、涨价、价格战 | `price_war`（Bertrand） |
| 拍卖、竞拍、出价、中标、竞价 | `auction`（Vickrey） |
| 谈判、协商、讨价、让步、妥协 | `negotiation` |
| 产量、产能、输出、份额、竞争 | `output_competition`（Cournot） |

领域模板可通过 `game_type_preference` 覆盖（如生态领域默认 Cournot）。

## 大白话结论卡片

每份报告均包含**第五章**——大白话结论卡片，将专业博弈论分析翻译为具体、无术语、可立即执行的指导：

```
──────────────────────────────────────────────────
  预算分配结论卡
──────────────────────────────────────────────────

**一句话策略**：
下一阶段，把可调配的预算按大概50%给运营部（主力），25%给市场部（维持），
15%给研发部（防守），10%给销售部（兜底）。每个季度根据实际效果微调一次。

**为什么这么分？**
运营部势头正猛（指标上升了21%），每一份预算投给它的回报率最高。
市场部变化不大，保持现有投入就够。
研发部和销售部正在后退，保留最低限度的预算防止崩盘即可。

**接下来具体怎么操作（人话版）**
**立即**：
  - 运营部：把份额拉到总盘约50%，集中火力推上去。
  - 市场部：维持约25%份额，不增不减，静观其变。
  - 研发部：保留约15%兜底，避免彻底崩盘。
  - 销售部：保留约10%兜底。

**盯住两个数字**：
- 如果组织效能指数的单季度变化掉到1.5%以下，就开会重新研究。
- 如果整个轨迹偏离预计方向超过10%，马上暂停所有大动作，先观察。

**最直白的总结**：
现在的局势就像打仗：运营部是冲在最前面的先锋，资源优先倾斜给它。
销售部是最后一道防线，留一点预算别让它垮就行。
中间的几个保持现状观望，等局势明朗了再调。

**各参与方权重排名**：
  1. 运营部 [主力] ↑21% — 建议份额约50%
  2. 市场部 [次主力] ↑7% — 建议份额约25%
  3. 研发部 [防守] ↓2% — 建议份额约15%
  4. 销售部 [兜底] ↓18% — 建议份额约10%
```

结论卡片使用**领域特定语言包**——7 个领域各有专属术语：
- 生态："保护资金"、"综合生态指数"、"种群数量"
- 个人："精力/时间"、"综合满意度指数"
- 社交："沟通精力/诚意"、"关系改善指数"
- 企业："预算"、"组织效能指数"
- 创意："创作资源"、"综合影响力指数"
- 城市："运力/服务资源"、"系统负载均衡度"
- 元认知："论证资源/发表机会"、"学术影响力指数"

## 多方权重排名

当博弈包含**3 个或以上参与方**时，结论卡片自动从二元（进攻方 vs 防守方）切换为**分层多方排名**：

**方向感知动量评分：**
- 正向动量玩家（增长 >5%）：满分——值得投入
- 中性动量玩家（-5% 至 +5%）：中等分——维持当前配置
- 负向动量玩家（下降 < -5%）：打折分——减少进一步投入

**数据驱动层级命名：**
- `主力`（Primary）：最强正向动量，~50–55% 份额
- `次主力`（Secondary）：次强正向动量，~25–28% 份额
- `维持`（Maintain）：接近中性，维持当前水平，~15–17% 份额
- `防守`（Defensive）：中度下滑，保留最低限度，~10–15% 份额
- `兜底`（Floor）：严重下滑，绝对最小托底，~5–10% 份额

层级名称**非固定**——根据每方实际轨迹动态分配。衰退 16% 的玩家会被标为"兜底"而非"维持"，无论其在排序中的位置。

2 方博弈保持原有二元进攻-防守格式不变。

## 核心设计原则

1. **纯 Python 标准库 + SQLite**——无 numpy、无 pandas、无 Redis、无外部计算库。表达式树求值器、特征提取引擎、Lorenz RK4 积分器、全部博弈模型均为纯 Python 手写实现。

2. **多进程架构**——每个智能体是独立的 `multiprocessing.Process`，拥有独立内存空间。能量管理器、繁殖器、清理器以 `threading.Thread` 形式在主进程中运行。所有跨进程通信通过单一 `multiprocessing.Queue`。

3. **SQLite WAL 模式**——支持所有进程和线程的并发读写，无需锁冲突。所有写操作使用指数退避重试处理瞬态锁竞争。无需独立数据库服务器。

4. **LLM 双模式**——整个用户面管道（解析 → 舆情 → 叙事）完全支持离线运行（正则 + 规则引擎）。启用 LLM 后每个阶段升级为领域感知智能。默认为离线模式——无需 API Key。

5. **领域优先设计**——所有提示词注入、术语替换、语言包均按领域组织。添加新领域只需注册 `DomainTemplate`——无需修改解析器、引擎、舆情分析器或叙事器代码。

6. **模板即参数，非数据**——领域模板描述"要找什么类型的东西"，绝不包含硬编码的实体名称、具体数值或领域公式。它们是参考模式，不是示例数据库。

7. **能量即通用适应度**——没有独立的损失函数。没有梯度下降。没有反向传播。能量是生存、繁殖和选择的唯一货币。能量公式刻意保持简单——`max(0, 1 - |error| / scale)`——使复杂性从智能体策略中涌现，而非来自适应度景观。

8. **数据驱动叙事**——规则引擎报告中的每一句话都由实际推演数据计算生成（轨迹、Lyapunov 指数、纳什收敛度、玩家轨迹）。没有填槽式静态报告模板。LLM 接收全部计算数据，并被指示引用具体数字。

9. **混沌即信息**——Lorenz 吸引子被特意选为其产生的结构化不可预测性。它既不是可轻易取平均的纯噪声，也不是可轻易记忆的简单周期。智能体必须进化出真正的非线性模型，而非仅仅模式匹配启发式。

10. **优雅降级**——每个组件都有回退方案：无精英智能体 → NGRC 多项式残差；无 LLM → 正则解析器 + 规则叙事器；无舆情 → 中性偏差；无领域匹配 → 通用模板。系统从不灾难性失败——它优雅降级至最佳可用模式。
